# AI auto-equip. Called from give_character_an_item whenever an AI-run
# character receives an item, so the AI actually benefits from the item system
# (equipping applies each item's modifier). Human players are excluded - they
# equip via the character-window Items menu.
#
# Runs in CHARACTER scope.
#
# Strategy: fill empty category slots, best-first. This effect no longer strips
# the existing loadout before re-equipping. The old unequip-then-reequip pass
# cost 85 extra if-blocks per item gained, churned the country _army modifiers
# of every combat item on every acquisition, and depended on
# has_any_other_same_category_item_equipped resolving correctly against a
# just-emptied equiped_item_list - which it did not, so on a character's very
# first acquisition nothing re-equipped at all. Slots are now filled and left
# alone; the player-facing Items menu is still the way to deliberately swap.
#
# The legacy hand-authored items below are ordered unique -> rare -> uncommon
# -> common so the best owned item claims a contested slot first. The previous
# ordering was the file's arbitrary authoring order, which meant a character
# holding both item_sword and item_masterwork_sword could end up wearing the
# common one. DO NOT re-sort this block by hand - rarity order is the point.

	if = {
		limit = { has_variable_list = item_list }
		# Element scope inside every_in_list is a bare flag, so step back to the
		# character with prev = { ... } and read the element as prev from there.
		# This is the same shape the shop's slot fill uses in omni_item_menu.txt;
		# save_scope_as on a flag element is not a proven form in this codebase.

			variable = item_list
			prev = {
				set_variable = { name = omni_shop_slot_autoequip value = prev }
				omni_equip_var_gen_item = { SLOT = autoequip }
				remove_variable = omni_shop_slot_autoequip
			}
		}
